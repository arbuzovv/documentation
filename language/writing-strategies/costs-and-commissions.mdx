title: "Расходы и комиссии"

---

Каждое исполнение платит комиссию и проходит через модель проскальзывания, а комиссия попадает в стоимость позиции и реализованный P&L, а не только в денежный баланс. Что взимается по умолчанию, зависит от способа запуска.

## Значения по умолчанию

Значения по умолчанию в движке заданы для американского рынка и выражены в долларах. Для инструментов Мосбиржи задавайте модель расходов явно — см. раздел «Комиссия для Мосбиржи» ниже.

|  | `run_simulation(...)` | `ziplime run` |
| --- | --- | --- |
| Акции | `PerShare(cost=0.001)` — 0,001 за бумагу, без минимума | `PerShare(cost=0.0)` — **без комиссии**, пока не передан `--commission-per-share` |
| Фьючерсы | `PerContract(cost=0.85)` плюс биржевые сборы по базовому тикеру | так же |
| Опционы | `PerOptionContract()` — 0,65 за контракт плюс 0,05 биржевого сбора | так же |
| Облигации | `PerBondTurnover(cost=0.0003)` — 3 б.п. от оборота | так же |
| Проскальзывание по акциям | `FixedBasisPointsSlippage(basis_points=5.0, volume_limit=0.1)` | `--slippage-bps 5.0`, тот же предел по объёму |
| Проскальзывание по фьючерсам | `VolatilityVolumeShare(volume_limit=0.05)` | так же |

<Warning>
  `ziplime run` по умолчанию не берёт комиссию по акциям. Для любого запуска, результатам которого вы собираетесь доверять, задайте комиссию явно.
</Warning>

## Комиссия для Мосбиржи

Брокерская комиссия Финама обычно считается в процентах от оборота, поэтому для акций Мосбиржи подходит `PerDollar` — доля от стоимости сделки (название модели историческое, валюта значения не имеет). Такую модель можно задать только через Python API: у CLI есть лишь комиссия за бумагу.

```python
from ziplime.finance.commission import PerDollar

result = await run_simulation(
    ...,
    trading_calendar="XMOS",
    equity_commission=PerDollar(cost=0.0004),   # порядка 0,04% от оборота
)
```

Стоимость позиций и расходы по рублёвым инструментам — например, **SBER**, **GAZP** или **LKOH** — считаются в рублях. Значение комиссии берите из актуальных условий вашего тарифа в Финаме: точные ставки могут меняться.

## Модели комиссий

```python
from ziplime.finance.commission import PerShare, PerDollar, PerContract, PerOptionContract
from ziplime.finance.commission.per_trade import PerTrade
```

| Модель | Класс активов | Что взимает |
| --- | --- | --- |
| `PerShare(cost, min_trade_cost)` | Акции | За бумагу, с необязательным минимумом за сделку |
| `PerDollar(cost)` | Акции | Долю от стоимости сделки |
| `PerTrade(cost)` | Любой | Фиксированную сумму за сделку |
| `PerContract(cost, exchange_fee, min_trade_cost)` | Фьючерсы | За контракт плюс биржевые сборы |
| `PerFutureTrade(cost)` | Фьючерсы | Фиксированную сумму за сделку с фьючерсом |
| `PerOptionContract(cost, exchange_fee, min_trade_cost)` | Опционы | За контракт плюс биржевые сборы |
| `PerBondTurnover(cost)` | Облигации | Долю от оборота |
| `NoCommission()` | Любой | Ничего — только для контрольного запуска |

## Модели проскальзывания

| Модель | Поведение |
| --- | --- |
| `FixedBasisPointsSlippage(basis_points=5.0, volume_limit=0.1)` | Фиксированное влияние на цену; каждое исполнение ограничено долей `volume_limit` от объёма бара. `basis_points=0` — контрольный запуск, в котором ограничение по объёму всё равно действует |
| `VolatilityVolumeShare(volume_limit=...)` | Влияние на цену по фьючерсам с учётом волатильности и доли в объёме |
| `NoSlippage()` | Исполнение по цене бара без влияния |

## Расходы в параметрах запуска

```python
from ziplime.finance.commission import PerDollar
from ziplime.finance.slippage.fixed_basis_points_slippage import FixedBasisPointsSlippage

result = await run_simulation(
    ...,
    equity_commission=PerDollar(cost=0.0004),
    equity_slippage=FixedBasisPointsSlippage(basis_points=5.0, volume_limit=0.1),
)
```

```bash
ziplime run -f sma.py -b moex -s SBER@MISX,GAZP@MISX -c XMOS \
  --start-date 2020-01-01 --end-date 2025-12-31 --commission-per-share 0.01 --slippage-bps 5
```

Расходы относятся к запуску, а не к стратегии. `context.set_commission(...)` и `context.set_slippage(...)` существуют для совместимости с Zipline; лучше задавать параметры запуска, чтобы модель расходов была видна рядом с результатом.

## Векторные запуски

Векторное ядро применяет те же модели комиссий и проскальзывания. Модель расходов, которую ядро применить не может, **останавливает запуск с указанием её имени** — иначе неоплаченные расходы проявились бы как более высокая доходность, а не как ошибка.

<Note>
  Реалистичная модель расходов уменьшает, но не устраняет расхождение между бэктестом и реальным результатом. Бэктест не может с полной точностью воспроизвести будущее.
</Note>
