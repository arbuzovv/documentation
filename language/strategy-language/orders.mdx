Заявки — асинхронные вызовы `context`. Выставляйте их в `handle_data` или в функциях по расписанию, но не в `initialize` и не в `before_trading_start`.

```python
from ziplime.finance.execution import MarketOrder

await context.order_target_percent(
    asset=context.asset,
    target=0.5,
    style=MarketOrder(),
)
```

## Стили исполнения

```python
from ziplime.finance.execution import (
    MarketOrder,
    LimitOrder,
    StopOrder,
    StopLimitOrder,
)
```

| Стиль | Пример | Значение |
| --- | --- | --- |
| `MarketOrder()` | `MarketOrder()` | Исполнение по цене исполнения запуска плюс проскальзывание |
| `LimitOrder(limit_price)` | `LimitOrder(300.0)` | Покупка не дороже лимита, продажа не дешевле |
| `StopOrder(stop_price)` | `StopOrder(290.0)` | Становится рыночной заявкой, когда достигнут стоп |
| `StopLimitOrder(limit_price, stop_price)` | `StopLimitOrder(302.0, 298.0)` | Становится лимитной заявкой, когда достигнут стоп |

## Фиксированное количество

### `await context.order(asset, amount, style, account_id=None, exchange_name=None)`

Положительное `amount` — покупка или закрытие короткой позиции; отрицательное — продажа или открытие короткой позиции.

```python
await context.order(context.asset, 100, style=MarketOrder())
await context.order(context.asset, -50, style=MarketOrder())
await context.order(context.asset, 100, style=LimitOrder(limit_price=300.0))
```

Количество указывается в бумагах. При реальной торговле через Финам оно округляется вниз до целых лотов — см. [«Реальная торговля через Финам»](/language/writing-strategies/live-trading).

## Фиксированная сумма

### `await context.order_value(asset, value, limit_price=None, stop_price=None, style=None, exchange_name=None)`

Купить или продать инструмент на сумму `value` в валюте портфеля. Передайте либо `style`, либо сокращённые цены: только `limit_price` — лимитная заявка, только `stop_price` — стоп, оба — стоп-лимит, ни одного — рыночная. Совмещение `style` с ценой вызывает ошибку.

```python
await context.order_value(context.asset, 50_000)
await context.order_value(context.asset, 50_000, limit_price=300.0)
```

## Целевые значения

### `await context.order_target(asset, target, style, exchange_name=None)`

Привести позицию к целевому числу бумаг или контрактов.

```python
await context.order_target(context.asset, 200, style=MarketOrder())
await context.order_target(context.asset, 0, style=MarketOrder())
```

### `await context.order_target_value(asset, target, style, exchange_name=None)`

Привести позицию к целевой стоимости в валюте портфеля.

### `await context.order_target_percent(asset, target, style, exchange_name=None)`

Привести позицию к целевой доле стоимости портфеля. `target` должен быть от `-1` до `1`. Количество уменьшается на прогнозную комиссию и проскальзывание, чтобы заявка помещалась в денежные средства, от которых она рассчитана.

```python
await context.order_target_percent(context.sber, 0.25, style=MarketOrder())
await context.order_target_percent(context.sber, 0.0, style=MarketOrder())
```

### `await context.order_percent(asset, percent, style, exchange_name=None)`

Заявка на долю стоимости портфеля **в дополнение** к текущей позиции. Это не целевое значение.

## Ребалансировка портфеля

### `await context.rebalance(weights, style=None, exchange_name=None)`

Держать ровно эти веса и ничего больше. Каждый названный листинг приводится к целевому весу, а **каждая не названная позиция закрывается** — эту половину стратегии часто забывают, и бумага, выпавшая из набора, тихо остаётся в портфеле.

```python
await context.rebalance({listing: 0.1 for listing in winners})
await context.rebalance({})          # закрыть всё
```

- Веса — доли стоимости портфеля, как в `order_target_percent`. Их сумма не проверяется на равенство 1.0, потому что фьючерсный портфель по построению использует плечо.
- `style` по умолчанию — `MarketOrder()`.
- Позиция, рынок которой в этот момент закрыт, остаётся как есть — без заявок и без закрытия (начиная с 2.11.0). Это важно для портфелей, где акции `MISX` соседствуют с фьючерсами `RTSX` с другими часами торгов.
- Называйте только листинги, у которых сегодня есть цена: заявка по листингу без цены вызывает ошибку.

## Открытые заявки

### `context.get_open_orders(asset=None)`

Рабочие заявки. Передайте инструмент, чтобы отфильтровать. Отменённые и отклонённые заявки из этого списка удаляются.

```python
if context.get_open_orders(context.asset):
    return
```

### `context.get_order(order_id, exchange_name)`

```python
order = context.get_order(order_id, exchange_name="MOEX")
if order is not None:
    print(order.status, order.filled, order.amount)
```

### `await context.cancel_order(order_id, exchange_name, relay_status=True)`

```python
for order in context.get_open_orders(context.asset):
    await context.cancel_order(order.id, exchange_name=order.exchange_name)
```

## Возвращаемый объект заявки

Методы заявок возвращают `Order` или `None`, если заявка не выставлена.

| Поле | Значение |
| --- | --- |
| `id` | Идентификатор заявки |
| `asset` | Листинг в заявке |
| `amount` | Запрошенное количество |
| `filled` | Исполненное количество |
| `open_amount` | Оставшееся количество |
| `status` | Текущий статус |
| `commission` | Накопленная комиссия |
| `dt` | Дата и время последнего обновления |
| `exchange_name` | Биржа, которой принадлежит заявка |

## Момент исполнения

| Где запускается | По умолчанию | Как переключить |
| --- | --- | --- |
| `ziplime run` | Следующий бар | `--same-bar-execution` |
| Локальный MCP-сервер | Следующий бар | — |
| `run_simulation(...)` | Тот же бар | `same_bar_execution=False` |

При исполнении на следующем баре заявка из `handle_data` исполняется на следующем баре, а `handle_data` видит портфель, в котором уже учтены прошлые исполнения. Исполнение на том же баре идёт по закрытию бара, на котором принято решение, — по цене, которой рынок ещё не показал.

Цена исполнения — одно поле бара: по умолчанию `close`, либо `open`, `high`, `low` (`--fill-price` / `price_used_in_order_execution`). На баре без объёма исполнения нет, а модель проскальзывания ограничивает исполнение долей объёма бара, поэтому крупная заявка может исполняться несколько баров.

## Целевые заявки и открытые заявки

Целевые функции считают от текущей позиции и **не** учитывают ещё не исполненные заявки. Два целевых вызова до исполнения дают лишний объём:

```python
await context.order_target_percent(asset, 0.5, style=MarketOrder())
await context.order_target_percent(asset, 0.5, style=MarketOrder())   # 100%, а не 50%
```

Проверяйте открытые заявки или используйте `context.rebalance`:

```python
if not context.get_open_orders(asset):
    await context.order_target_percent(asset, 0.5, style=MarketOrder())
```

## Что вызывает ошибку

- Заявка по `ContinuousFuture` — заявляйте `await data.current_contract(cf)`.
- Заявка по `FuturesContract` из `context.future_symbol` — заявляйте листинг из `futures_symbol`, `futures_chain` или `front_contract`.
- Заявка по листингу, рынок которого закрыт, — ошибка называет календарь листинга и календарь симуляции.
- Заявка, которую отклоняет [торговое ограничение](/language/strategy-language/scheduling-and-controls), при значении по умолчанию `on_error="fail"`.
