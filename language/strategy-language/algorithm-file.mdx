Стратегия Ziplime — это Python-файл с функциями жизненного цикла. Создавать подкласс не нужно: определите функции, которые должен вызывать движок, а состояние стратегии храните в `context`. Файл импортируется, поэтому код на уровне модуля выполняется — оставляйте там только импорты, константы и определения.

## Каркас файла

```python
from ziplime.domain.bar_data import BarData
from ziplime.finance.execution import MarketOrder
from ziplime.trading.trading_algorithm import TradingAlgorithm


async def initialize(context: TradingAlgorithm):
    context.asset = await context.symbol("SBER@MISX")
    context.short_window = 20
    context.long_window = 100


async def handle_data(context: TradingAlgorithm, data: BarData):
    history = await data.history(
        assets=[context.asset],
        fields=["close"],
        bar_count=context.long_window,
    )
    closes = history["close"].to_numpy()

    if len(closes) < context.long_window:
        return

    short_ma = closes[-context.short_window:].mean()
    long_ma = closes.mean()
    target = 1.0 if short_ma > long_ma else 0.0

    await context.order_target_percent(context.asset, target, style=MarketOrder())
    context.record(short_ma=short_ma, long_ma=long_ma)
```

Импортировать `TradingAlgorithm` и `BarData` необязательно: аннотации типов дают редактору автодополнение для `context` и `data`.

## Функции жизненного цикла

| Функция | Обязательна | Как объявлять | Когда вызывается |
| --- | --- | --- | --- |
| `initialize(context)` | На практике да | `async def` | Один раз до первого бара |
| `handle_data(context, data)` | Да — без неё стратегия не торгует | `async def` | На каждом баре, с частотой `emission_rate` |
| `before_trading_start(context, data)` | Нет | `async def` | Раз в сессию, до открытия |
| `compute_signals(context, prices)` | Нет | `def` | Один раз по всей истории, до первого бара |
| `analyze(context, perf)` | Нет | `def` | Один раз после запуска |

Вместо любой функции, которую вы не определили, движок подставляет пустую.

## `initialize(context)`

Используйте её, чтобы:

- Найти инструменты.
- Сохранить константы и изменяемое состояние в `context`.
- Зарегистрировать функции по расписанию и задать торговые ограничения.
- Подключить наборы данных через `context.huggingface_dataset(...)`.
- Подключить пайплайны.
- Прочитать конфигурацию из `context.algorithm.config`.

```python
async def initialize(context):
    context.stocks = [
        await context.symbol("SBER", mic="MISX"),
        await context.symbol("GAZP@MISX"),
    ]
    context.max_weight = 0.25
```

Не выставляйте заявки в `initialize`: текущего бара ещё нет.

## `handle_data(context, data)`

Используйте её, чтобы читать текущие и исторические значения, рассчитывать сигналы, проверять денежные средства, позиции и открытые заявки, выставлять и отменять заявки и записывать метрики.

```python
async def handle_data(context, data):
    current = await data.current(assets=[context.asset], fields=["close", "volume"])
    close = current["close"][0]
    volume = current["volume"][0]

    if volume > 0 and close > context.entry_price:
        await context.order_target_percent(context.asset, 1.0, style=MarketOrder())

    context.record(close=close)
```

## `before_trading_start(context, data)`

Необязательная, вызывается раз в сессию до обычной обработки баров. Объявляйте её через `async def`: любое чтение данных — корутина, и движок ожидает эту функцию, если она корутина. Обычный `def` тоже выполнится, но вызвать в нём `await data...` нельзя.

Используйте её, чтобы сбросить дневное состояние, получить результаты пайплайна или подготовить набор инструментов на день. Заявки здесь запрещены.

```python
async def before_trading_start(context, data):
    context.traded_this_session = False
    context.universe = await context.universe_symbols("IMOEX@MISX")
```

## `analyze(context, perf)`

Необязательная, вызывается один раз после завершения симуляции. `perf` — DataFrame **pandas** с одной строкой на сессию, включая столбцы, записанные через `context.record(...)`.

```python
def analyze(context, perf):
    print(perf[["portfolio_value", "returns"]].tail())
    print("Итоговая стоимость портфеля:", perf["portfolio_value"].iloc[-1])
```

<Warning>
  Объявляйте `analyze` через обычный `def`. Сейчас движок вызывает её без `await`, поэтому `async def analyze` никогда не выполнится. (`check_strategy_code` локального MCP-сервера пока требует `async def` для всех функций — для `analyze` следуйте этой странице.)
</Warning>

## `compute_signals(context, prices)` и `WARMUP`

Необязательная. Возвращает индикаторы, рассчитанные по целым массивам; читайте их по барам через `context.signals`. Сколько баров истории им нужно, объявите в константе `WARMUP` на уровне модуля. Подробнее — в разделе [«Векторные сигналы»](/language/strategy-language/vectorized-signals).

```python
WARMUP = 60

def compute_signals(context, prices):
    return {"slow": prices.close.rolling(60).mean()}
```

## Хранение состояния

Всё, что должно сохраняться между барами, храните в атрибутах `context`:

```python
async def initialize(context):
    context.last_rebalance_date = None
    context.stocks = [await context.symbol("SBER@MISX")]


async def handle_data(context, data):
    context.last_seen_dt = context.get_datetime()
```

Не храните состояние стратегии в изменяемых глобальных переменных модуля: они переживают перезапуск в том же процессе.

## Конфигурация алгоритма

Объявите подкласс `BaseAlgorithmConfig` на уровне модуля, и движок загрузит его из JSON-файла, переданного в `run_simulation(..., config_file=...)`.

```python
from ziplime.config.base_algorithm_config import BaseAlgorithmConfig


class AlgorithmConfig(BaseAlgorithmConfig):
    symbols: list[str] = ["SBER@MISX", "GAZP@MISX"]
    target_weight: float = 0.5


async def initialize(context):
    cfg = context.algorithm.config
    context.stocks = [await context.symbol(symbol) for symbol in cfg.symbols]
    context.target_weight = cfg.target_weight
```

```json
{
  "symbols": ["SBER@MISX", "GAZP@MISX", "LKOH@MISX"],
  "target_weight": 0.33
}
```

Даты, капитал, бандл, бенчмарк, календарь, комиссия и проскальзывание относятся к запуску, а не к коду. Если задавать их внутри стратегии, это либо ничего не изменит, либо будет противоречить параметрам запуска.

## Частые ошибки

| Ошибка | Как исправить |
| --- | --- |
| Пропущен `await` у `context.symbol`, `data.current`, `data.history` или заявки | Добавьте `await`. Иначе ничего не сообщит об ошибке |
| `.iloc`, `.loc`, `.at` на результатах `data` | Это фреймы Polars: `df["close"][-1]`, `df["close"].to_numpy()` |
| `analyze` объявлена как `async def` | Используйте обычный `def analyze(...)` |
| Заявки в `initialize` или `before_trading_start` | Выставляйте их в `handle_data` или в функции по расписанию |
| Выдуманный MIC в `TICKER@MIC` | Для акций Мосбиржи — `MISX`, для срочного рынка — `RTSX`. Если не уверены в площадке, пишите тикер без MIC |
| Заявка по тикеру, которого нет в бандле | Сначала загрузите его: запуск знает только то, что есть в бандле |
| Свои переменные в `context.assets` | Это имя занято движком — используйте `context.stocks`, `context.universe` и т. п. |
