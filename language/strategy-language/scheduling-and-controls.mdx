Используйте функции по расписанию или фильтры по календарю, если стратегия должна действовать в определённое время, а не на каждом баре. Используйте ограничения, чтобы проверять правила управления рисками до того, как заявка будет принята.

## Фильтры по календарю

Самый простой способ ребалансироваться раз в неделю или месяц — проверка в начале `handle_data`:

```python
async def handle_data(context, data):
    if not context.is_month_start():     # или context.is_week_start()
        return
    ...
```

Обе функции читают торговый календарь симуляции, поэтому праздники Мосбиржи учитываются без арифметики дат. Это обычные вызовы, без `await`.

## Функции по расписанию

### `context.schedule_function(func, date_rule=None, time_rule=None, half_days=True, calendar=None)`

Регистрирует асинхронную функцию с той же сигнатурой, что у `handle_data`.

```python
from ziplime.finance.execution import MarketOrder
from ziplime.utils.events import date_rules, time_rules


async def initialize(context):
    context.asset = await context.symbol("SBER@MISX")
    context.schedule_function(
        rebalance,
        date_rule=date_rules.week_start(),
        time_rule=time_rules.market_open(minutes=30),
    )


async def rebalance(context, data):
    await context.order_target_percent(context.asset, 1.0, style=MarketOrder())
```

- `date_rule` по умолчанию — каждый торговый день.
- `time_rule` работает на **любой внутридневной частоте** — 1 минута, 5 минут, час. В дневном запуске на сессию приходится один бар, поэтому правило времени игнорируется.
- Передавайте правило времени по имени параметра. Правило времени на месте `date_rule` принимается с предупреждением.

## Правила дат

```python
from ziplime.utils.events import date_rules
```

| Правило | Значение |
| --- | --- |
| `date_rules.every_day()` | Каждый торговый день |
| `date_rules.week_start(days_offset=0)` | N-й торговый день каждой недели |
| `date_rules.week_end(days_offset=0)` | За N торговых дней до конца недели |
| `date_rules.month_start(days_offset=0)` | N-й торговый день каждого месяца |
| `date_rules.month_end(days_offset=0)` | За N торговых дней до конца месяца |

## Правила времени

```python
from ziplime.utils.events import time_rules
```

| Правило | Значение |
| --- | --- |
| `time_rules.market_open(hours=0, minutes=30)` | После открытия рынка |
| `time_rules.market_close(minutes=15)` | До закрытия рынка |
| `time_rules.every_minute()` | Каждый бар внутридневного запуска |

Смещение должно быть от 1 минуты до 12 часов.

## Календари

`schedule_function` по умолчанию использует торговый календарь симуляции — для Мосбиржи это `XMOS`, который вы передали при запуске. Параметр `calendar` принимает только американские значения `calendars.US_EQUITIES` и `calendars.US_FUTURES`, любое другое значение вызывает ошибку. Поэтому для стратегий на Мосбирже `calendar` не передавайте:

```python
context.schedule_function(
    rebalance,
    date_rule=date_rules.month_end(),
    time_rule=time_rules.market_close(minutes=30),
)
```

О запусках, которые объединяют несколько площадок — например, акции `MISX` и фьючерсы `RTSX`, — читайте в разделе [«Площадки и календари»](/language/strategy-language/venues-and-calendars).

## Какая функция для чего

| Функция | Можно выставлять заявки? | Как объявлять | Типичное использование |
| --- | --- | --- | --- |
| `before_trading_start` | Нет | `async def` | Подготовить набор инструментов, сбросить дневное состояние, получить результаты пайплайна |
| Функция по расписанию | Да | `async def` | Ребалансировка, выход, снижение риска в заданное время |
| `handle_data` | Да | `async def` | Торговая логика на каждом баре |

## Торговые ограничения

Ограничения задаются в `initialize` и проверяются для каждой заявки до её размещения. Начиная с 2.10.3 они **действительно применяются** — прежние версии принимали лимиты, но не соблюдали ни одного.

```python
async def initialize(context):
    context.set_long_only()
    context.set_max_leverage(1.5)
    context.set_max_position_size(asset=None, max_shares=10_000, max_notional=5_000_000)
    context.set_max_order_size(asset=None, max_shares=5_000, max_notional=2_500_000)
    context.set_max_order_count(10)
```

| Ограничение | Что ограничивает |
| --- | --- |
| `set_long_only(on_error="fail")` | Ни одна заявка не может открыть короткую позицию |
| `set_max_leverage(max_leverage)` | Плечо счёта. `run_simulation(max_leverage=...)` и `ziplime run --max-leverage` тоже его регистрируют (по умолчанию 1.0) |
| `set_min_leverage(min_leverage, grace_period)` | Минимальное плечо после льготного периода |
| `set_max_position_size(asset=None, max_shares=None, max_notional=None, on_error="fail")` | Абсолютный размер позиции — по инструменту или для всех при `asset=None` |
| `set_max_order_size(asset=None, max_shares=None, max_notional=None, on_error="fail")` | Размер любой отдельной заявки |
| `set_max_order_count(max_count, on_error="fail")` | Число заявок за день |
| `set_asset_restrictions(restrictions, on_error="fail")` | Список запрещённых инструментов |

`max_notional` задаётся в валюте портфеля — для рублёвых инструментов в рублях.

### Поведение при нарушении

При `on_error="fail"` (по умолчанию) заявка-нарушитель вызывает `TradingControlViolation`. При `on_error="log"` нарушение записывается в журнал как ошибка, а заявка проходит.

## Запрет на инструменты

```python
from ziplime.finance.asset_restrictions import StaticRestrictions


async def initialize(context):
    restricted = StaticRestrictions([context.restricted_asset])
    context.set_asset_restrictions(restricted)
```

Для запрещённых инструментов `data.can_trade` тоже возвращает `False`.

## Политики отмены

```python
from ziplime.finance.cancel_policy import EODCancel, NeverCancel


async def initialize(context):
    context.set_cancel_policy(EODCancel(warn_on_cancel=True))
```

| Политика | Значение |
| --- | --- |
| `EODCancel(warn_on_cancel=True)` | Отменять открытые заявки в конце сессии |
| `NeverCancel()` | Оставлять открытые заявки, пока они не исполнены или не отменены |

## Комиссии и проскальзывание

Расходы относятся к запуску, а не к стратегии: передавайте их в `run_simulation(...)` или CLI. Подробнее — в разделе [«Расходы и комиссии»](/language/writing-strategies/costs-and-commissions).
