Ziplime сохраняет событийную модель стратегий классического Zipline и zipline-reloaded, но не является заменой один к одному. Главные отличия: асинхронные функции стратегии, фреймы Polars, явные стили исполнения и исполнение на следующем баре по умолчанию.

## Что остаётся прежним

- Постоянное состояние стратегии хранится в `context`.
- `initialize` настраивает, `handle_data` торгует бар за баром.
- `schedule_function` с `date_rules` и `time_rules`, `record`, `order_target_percent`, пайплайны, торговые ограничения.

## Краткая таблица соответствий

| Классический Zipline | Ziplime |
| --- | --- |
| `def initialize(context)` | `async def initialize(context)` |
| `def handle_data(context, data)` | `async def handle_data(context, data)` |
| `def before_trading_start(context, data)` | `async def before_trading_start(context, data)` |
| `asset = symbol("SBER")` | `asset = await context.symbol("SBER@MISX")` |
| `symbols("SBER", "GAZP")` | `await context.symbols("SBER@MISX", "GAZP@MISX")` |
| `data.current(asset, "close")` | `(await data.current(assets=[asset], fields=["close"]))["close"][0]` |
| `data.history(asset, "close", 20, "1d")` | `await data.history(assets=[asset], fields=["close"], bar_count=20)` |
| `data.can_trade(asset)` | `data.can_trade([asset])[asset]` |
| `order(asset, 100)` | `await context.order(asset, 100, style=MarketOrder())` |
| `order_target_percent(asset, 0.5)` | `await context.order_target_percent(asset, 0.5, style=MarketOrder())` |
| `context.portfolio.positions[asset].amount` | `await context.portfolio.get_asset_positions_amount(asset)` |
| pandas из `data.*` | Polars из `data.*` |
| `run_algorithm(...)` | `ziplime run ...` или `run_simulation(...)` |

## Импорты

Импортируйте то, что используете: файл алгоритма — обычный модуль Python. Предпочитайте методы `context` функциям `zipline.api`:

```python
from ziplime.finance.execution import MarketOrder
from ziplime.utils.events import date_rules, time_rules
```

`ziplime.api` существует для совместимости, но в асинхронном коде вызовы `context` читаются яснее.

## Функции жизненного цикла

Классический Zipline:

```python
def initialize(context):
    context.asset = symbol("SBER")


def handle_data(context, data):
    price = data.current(context.asset, "close")
    if price > 300:
        order_target_percent(context.asset, 1.0)
```

Ziplime:

```python
from ziplime.finance.execution import MarketOrder


async def initialize(context):
    context.asset = await context.symbol("SBER@MISX")


async def handle_data(context, data):
    current = await data.current(assets=[context.asset], fields=["close"])
    price = current["close"][0]

    if price > 300:
        await context.order_target_percent(context.asset, 1.0, style=MarketOrder())
```

`before_trading_start` объявляйте через `async def`, чтобы в ней можно было ждать чтения данных. `analyze(context, perf)` остаётся обычным `def`, а `perf` по-прежнему DataFrame pandas.

<Warning>
  Пропущенный `await` не вызывает ошибку. Вызов возвращает корутину, которая так и не выполнится, и перенесённая стратегия молча не выставляет ни одной заявки.
</Warning>

## Рыночные данные

Ziplime ожидает списки и возвращает DataFrame Polars со столбцами `date`, `sid` и запрошенными полями:

```python
history = await data.history(assets=[asset], fields=["close"], bar_count=20)
mean_close = history["close"].mean()
last_close = history["close"][-1]
```

У фрейма Polars нет `.iloc`, `.loc`, `.at` и `.iat`. Если старый код завязан на pandas, явно преобразуйте фрейм через `history.to_pandas()`; в новом коде предпочитайте выражения Polars.

`data.history` не включает текущий бар. Если сигналу он нужен, прочитайте его через `data.current`.

## Заявки

Заявки асинхронны и принимают стиль исполнения:

```python
from ziplime.finance.execution import MarketOrder, LimitOrder

await context.order(asset, 100, style=MarketOrder())
await context.order(asset, 100, style=LimitOrder(limit_price=300.0))
await context.order_value(asset, 50_000, limit_price=300.0)
```

Многие ребалансировщики на Zipline проходят циклом по `order_target_percent`, а затем закрывают оставшееся. `context.rebalance(weights)` делает и то и другое:

```python
await context.rebalance({asset: 1.0 / len(winners) for asset in winners})
```

## Момент исполнения меняет результаты

CLI и MCP-сервер по умолчанию исполняют заявки **на следующем баре**; в типичной настройке Zipline исполнение шло на том же баре. Перенесённый бэктест будет отличаться — эта разница и есть заглядывание в будущее, которое было в старой настройке. `run_simulation` по-прежнему по умолчанию исполняет на том же баре — передайте `same_bar_execution=False`, чтобы сравнивать сопоставимое.

## Тикеры

```python
asset = await context.symbol("SBER")
asset = await context.symbol("SBER", mic="MISX")
asset = await context.symbol("SBER@MISX")
```

MIC указывайте, когда тикер есть на нескольких площадках. Для акций Мосбиржи это `MISX`, для срочного рынка — `RTSX`. Для именованных наборов `await context.universe_symbols("IMOEX@MISX")` возвращает торгуемые листинги и следует за изменениями состава во времени.

## Расписание

```python
from ziplime.finance.execution import MarketOrder
from ziplime.utils.events import date_rules, time_rules


async def initialize(context):
    context.schedule_function(
        rebalance,
        date_rule=date_rules.month_end(),
        time_rule=time_rules.market_close(minutes=30),
    )


async def rebalance(context, data):
    await context.order_target_percent(context.asset, 1.0, style=MarketOrder())
```

Правила времени работают на любой внутридневной частоте; в дневном запуске правило времени игнорируется. Для простой еженедельной или ежемесячной ребалансировки часто достаточно строки `if not context.is_month_start(): return` в начале `handle_data`.

## Портфель

Позиции хранятся с ключом по бирже, счёту и листингу, поэтому пользуйтесь вспомогательными методами:

```python
cash = context.portfolio.cash
amount = await context.portfolio.get_asset_positions_amount(asset)
value = await context.portfolio.get_asset_positions_value(asset)
```

## Пайплайны

Pipeline API похож на Zipline — `Pipeline`, `EquityPricing`, `CustomFactor`, фильтры, `attach_pipeline`, `pipeline_output`. Цены через `EquityPricing` — стандартный путь; собственным наборам данных нужны собственные загрузчики. Для альтернативных данных обычно проще [данные на момент публикации](/language/strategy-language/point-in-time-datasets) — например, MOEX AlgoPack.

## Запуск перенесённого алгоритма

```bash
ziplime ingest-assets -p finam
ziplime ingest -p finam -c XMOS -b moex -s SBER@MISX,GAZP@MISX \
  --start-date 2015-01-01 --end-date 2025-12-31
ziplime run -f my_migrated_algo.py -b moex -s SBER@MISX,GAZP@MISX -c XMOS \
  --start-date 2016-01-01 --end-date 2025-12-31 --capital-base 1000000
```

Или из Python через `run_simulation(...)` — там же задаётся процентная комиссия, см. [«Установка и запуск»](/language/introduction/install-and-run).

## Полный пример «до и после»

Классический Zipline:

```python
from zipline.api import order_target_percent, record, symbol


def initialize(context):
    context.asset = symbol("SBER")
    context.window = 20


def handle_data(context, data):
    history = data.history(context.asset, "close", context.window, "1d")
    price = data.current(context.asset, "close")
    mean_price = history.mean()

    if price > mean_price:
        order_target_percent(context.asset, 1.0)
    else:
        order_target_percent(context.asset, 0.0)

    record(price=price, mean_price=mean_price)
```

Ziplime:

```python
from ziplime.finance.execution import MarketOrder


async def initialize(context):
    context.asset = await context.symbol("SBER@MISX")
    context.window = 20


async def handle_data(context, data):
    history = await data.history(
        assets=[context.asset], fields=["close"], bar_count=context.window,
    )
    if len(history) < context.window:
        return
    current = await data.current(assets=[context.asset], fields=["close"])

    price = current["close"][0]
    mean_price = history["close"].mean()
    target = 1.0 if price > mean_price else 0.0

    if not context.get_open_orders(context.asset):
        await context.order_target_percent(context.asset, target, style=MarketOrder())

    context.record(price=price, mean_price=mean_price, target=target)
```

## Чек-лист миграции

- Объявите `initialize`, `handle_data`, `before_trading_start` и функции по расписанию через `async def`; `analyze` оставьте обычным `def`.
- Добавьте `await` к поиску инструментов, чтению данных, заявкам и отменам.
- Передавайте списки в `data.current` и `data.history`; замените индексацию pandas на Polars.
- Добавьте в заявки стиль исполнения, например `MarketOrder()`.
- Замените `portfolio.positions[asset]` вспомогательными методами портфеля.
- Сопоставьте тикеры с площадками Мосбиржи (`SBER@MISX`) и используйте календарь `XMOS`.
- Пересоберите данные: `ziplime ingest-assets -p finam`, затем `ziplime ingest -p finam`.
- Ожидайте других цифр из-за исполнения на следующем баре и действующих ограничений; задайте реальную комиссию.
